Wristbox: a phone can stand in for the wearable

Amazon ships no simulator for Bee, so every test until now ran against a
fixture that can only replay an attack we wrote ourselves. That does not test
the actual threat model, which is a bystander saying something adversarial in
a phrasing nobody anticipated.

Wristbox is a small local server that speaks the same MCP tool surface, so the
unmodified BeeClient talks to it with nothing changed. A phone microphone feeds
it, and the real sanitiser processes live, improvised speech. Verified end to
end: live speech in, WARNING surfaced, content fenced, nothing acted on.

Two bugs found while building it, both fixed with tests:

  - BEE_MCP_TRANSPORT and friends were not trimmed, so the very common
    "set BEE_MCP_TRANSPORT=http && next" on Windows failed with
    "must be stdio or http, not 'http '". Baffling, and found by doing it.
  - The store tie-break claimed recency but compared timestamps, which ties
    during fast speech and then falls back to insertion order, returning the
    older turn. It now uses a monotonic sequence.

The page leads with a banner saying it is not the Amazon Bee product, because
a project arguing that the trust boundary must be honest cannot afford a
stand-in that looks like the real thing. The ingest endpoint is token-guarded
and LAN mode is opt-in, because an open ingest is itself an injection vector
into the stand-in.

87 tests, 30 smoke, 6 auth, all green.
